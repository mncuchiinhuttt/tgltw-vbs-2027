\begin{abstract}
Interactive video retrieval is a joint test of retrieval quality, operator effort, interface latency, and reliable submission. We present TGLTW-RMIT, our live-first multimodal system for the Video Browser Showdown (VBS) 2027. TGLTW-RMIT combines offline visual, speech, OCR, metadata, and ambient-audio evidence with approximate vector search, payload full-text retrieval, reciprocal-rank fusion, and bounded precision escalation. Its task router supports the official KIS-V, KIS-T, KIS-C, AVS, and VQA modes while retaining source-video and frame provenance throughout browsing and DRES submission. For VQA, a strict evidence contract accepts an answer only when a real candidate frame is resolved, the response is valid JSON, and the identity shown to the operator is the identity seen by the model. We describe the implementation and a reproducible live/offline evaluation protocol; quantitative results are reserved for a frozen benchmark run. Source, updates, and deployment links are collected on the public \projectpage.
\keywords{Video retrieval \and Multimodal search \and Interactive retrieval \and Video Browser Showdown \and Grounded VQA}
\end{abstract}

\section{Introduction}
\label{sec:intro}

The Video Browser Showdown evaluates exploratory video-search tools in a timed, public setting. An operator must interpret a task, retrieve evidence, inspect a video, and submit a temporal result before the clock expires. The 2027 call expects mostly textual KIS, conversational KIS, VQA, and AVS tasks, with KIS-V as the minority; it also requires an extended demo paper of six content pages plus up to two pages of references, including a screenshot and a description of interactive search~\cite{vbs2027call}. This makes predictable interaction a first-class system property: an unbounded precision model can be less useful live than a slightly weaker model with known latency.

TGLTW-RMIT is organized around that constraint. It keeps a fast default path based on already-built indexes, approximate HNSW retrieval~\cite{malkov2018efficient}, payload search, rank fusion, and a small reranking head. Exact search, larger candidate pools, verification, and in-video refinement are explicit per-request actions. This allows the operator to spend time only on difficult candidates and lets later evaluation measure the cost of each escalation.

The paper makes three implementation contributions:
\begin{enumerate}
    \item a multimodal offline-to-online architecture that preserves media provenance from indexed evidence to UI and DRES;
    \item one explicit live contract for the five VBS task modes, with different query interfaces but shared candidate, browsing, feedback, and submission primitives; and
    \item grounded VQA that fails closed on unavailable media, malformed output, invalid confidence, or candidate/frame mismatch.
\end{enumerate}

This is an engineering description rather than a completed leaderboard report. The repository currently contains the system and logging paths, but the final VBS query set, index manifest, and runtime configuration must be frozen before accuracy or latency claims are filled. The public \projectpage{} links the source repository, implementation notes, paper source, and deployment entry points.

\section{Positioning and VBS Setting}
\label{sec:setting}

Interactive multimedia retrieval work consistently combines semantic representations with fast browsing and feedback. The VBS literature emphasizes the interaction trace and time-to-submission in addition to retrieval quality~\cite{rossetto2025vbs}; performance evaluation work likewise recommends reporting system and human-action latency separately~\cite{sauter2024performance}. Local challenge systems provide useful precedents for OCR/ASR evidence, query expansion, temporal search, reranking, and feedback~\cite{doan2025kpi,le2025fustar}. TGLTW-RMIT uses the same broad principles but does not claim to reproduce those systems' model stacks. Its current online path uses Qdrant-style vector collections, dense and payload text retrieval, reciprocal-rank fusion (RRF)~\cite{cormack2009reciprocal}, and bounded operator actions. Query rewriting and vector feedback are deliberately narrower than open-ended multi-query or reweighting systems~\cite{buitran2025query,phat2025revimm}.

The official 2027 corpus includes the complete V3C collection, an extended marine-video collection, and the GynSurg/LapGynLHE laparoscopic collection; most tasks are expected to use V3C~\cite{vbs2027call}. V3C provides broad Creative Commons video and shot-level access~\cite{rossetto2019v3c}, while MVK and GynSurg represent domain-specific marine and surgical content~\cite{truong2023mvk,nasirihaghighi2025gynsurg}. The final run must record the exact accessible shards, video IDs, durations, checksums, keyframe/shot version, collection schema, and data-agreement status. The legacy running snapshot and the newer source indexer are therefore reported as separate implementation states until a re-index is audited.

\subsection{Offline evidence and provenance}
For each video, preprocessing reuses official keyframes when their mapping is known, otherwise detects shots and selects representative frames. The source pipeline can add OCR, object labels, faster-whisper speech segments, ambient-audio windows, optional VLM narratives, and named visual vectors; these fields are not assumed to be populated in the legacy deployment. Visual, speech, and audio points are kept in separate native temporal units. Every candidate carries a source video or file identifier, a frame index when available, a timestamp, and the evidence fields actually indexed. This identity is the join key for the UI, VQA, logs, and DRES.

\subsection{Retrieval and interaction}
Text queries enter a bounded conversational rewrite (CQR) when session context exists and may produce one HyDE-style hypothetical description. Dense lists and payload full-text lists (OCR, metadata, speech, captions, and object names when available) are combined with
\begin{equation*}
\operatorname{RRF}(x)=\sum_{\ell\in\mathcal{L}}\frac{1}{k+\operatorname{rank}_{\ell}(x)}.
\end{equation*}
Temporal coherence groups nearby hits from one video, while scene diversification limits near-duplicate frames. The browser exposes result cards, source media, timestamps, metadata, playback, query-by-example, positive/negative feedback, manual in-video search, and DRES submission. The backend records query, action, candidate, and submission events separately, allowing human-action time to be distinguished from retrieval time.

\paragraph{KIS-V.} An uploaded clip is sampled at a bounded budget (currently at most eight readable positions), embedded with the primary visual encoder, and searched against the visual collection. Per-sample hits are merged and deduplicated by indexed point. The default path does not invoke HyDE, sparse search, or VLM reranking; the resulting card retains source video, frame, timestamp, and DRES actions.

\paragraph{KIS-T.} A text description enters the Type-1 route. CQR resolves references only when bounded session history exists; HyDE is one optional hypothetical description, not an open-ended paraphrase loop. Dense, secondary-vector, and payload-text lists are fused with RRF, then temporal coherence and scene diversity shape the candidate grid. A small VLM head can rerank the pool; exact search, a larger HNSW pool, and verification are explicit overrides.

\paragraph{KIS-C.} Conversational search is stateful policy around KIS-T, not a second index. The session stores the resolved query and short confirmed/rejected candidate descriptions. If the pool is ambiguous, the system asks one facet-specific clarification question and boosts the associated candidates. Positive/negative feedback performs a lightweight Rocchio-style vector update and records the action for the next turn; it does not add an unbounded agent loop.

\paragraph{AVS.} AVS reuses broad KIS-T retrieval but optimizes the final list for multiple shots. Temporal coherence and scene/video diversification reduce near duplicates, after which the operator groups candidates by source video, browses within promising media, and chooses shots. The DRES client maintains a per-task submitted-video set and returns a soft duplicate warning rather than silently issuing a second submission; the official live judge remains the authority for AVS correctness.

\paragraph{VQA.} The question is decomposed into a bounded candidate search. A candidate reaches the VLM only after a real keyframe is loaded or its source video is decoded; the canonical frame index is preferred, with timestamp as a legacy fallback. The response must contain \code{found=true}, a non-empty answer, and finite confidence in $[0,1]$. Missing media, invalid JSON, timeout, unknown answer, invalid confidence, or identity mismatch returns \code{UNKNOWN/N/A} and score zero. For a valid answer, the same candidate ID, video ID, and frame index are returned to the API and UI; invalid outputs retain the candidate payload but do not populate answer identity.

\section{Evaluation Protocol}
\label{sec:evaluation}

The paper separates the official live DRES outcome from a controlled offline replay. The repository currently has a thin REST client and JSONL interaction logging; before the event, login, current-task, submission, and log payloads must be checked against the exact VBS OpenAPI contract. During VBS, the record must preserve the DRES task/session IDs, mode, task start/end, every query and clarification, candidates shown, submissions in order, judge or ground-truth outcome, and model/index/configuration hashes. The live track reports official score/rank, time-to-first and time-to-correct submission, correct and false submissions, total submissions, and the ordered interaction trace. KIS-C retains its clarification transcript; AVS retains source-video identity and temporal ranges; VQA retains evidence identity.

Offline replay is diagnostic, not a VBS leaderboard score. It uses a frozen manifest, query split, relevance/evidence labels, index snapshot, model revisions, hardware, timeouts, configuration hash, and raw predictions. Known-item tasks report Recall@1/5/10/20, MRR, nDCG@10, target-video hit, and frame/interval hit. AVS reports unique-video coverage and duplicate rate only when a frozen accepted-shot annotation exists. VQA reports answer correctness, candidate localization, grounded-answer rate, evidence-identity parity, and p50/p95 latency. All tracks report query, retrieval, reranking, VLM, end-to-end, and human-action latency separately.

The primary ablation is the quality--latency frontier: dense-only versus sparse-only versus RRF, then RRF with HyDE, bounded VLM reranking, temporal coherence, diversification, and grounded verification. Exact search and larger HNSW settings are measured as alternatives to the live default. Operational failures—empty retrieval, media decode failure, malformed VLM response, timeout, provenance mismatch, and duplicate/wrong submission—are counted alongside quality metrics. No result cell is populated until the manifest and index revision are frozen.

\section{Limitations and Conclusion}
\label{sec:conclusion}

The current deployment still has a migration boundary between legacy Qdrant collections and the newer source-index schema, so optional enrichment fields cannot be treated as universal. Sequential VLM verification may dominate p95 latency, and provider/model revisions can change token semantics and response formatting. AVS and some KIS-C outcomes depend on operator decisions and live judging; offline recall cannot reproduce them. The final release should publish the manifest, index schema and version, configuration, model revisions, raw predictions, metric script, interaction trace, and failure logs.

TGLTW-RMIT presents a compact live-first design for VBS 2027: multimodal evidence is indexed offline, bounded dense/sparse retrieval supports the five task modes, and precision operations are visible operator choices. The central reliability safeguard is candidate-specific VQA grounding, which prevents unavailable or mismatched media from becoming a seemingly valid answer. The next milestone is a frozen replay and an on-site rehearsal that fills the evaluation record without changing the live configuration.
